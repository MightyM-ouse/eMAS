## Executive summary

All 15 available directory inputs were scanned through the actual supported entry
point in PowerShell 7.6.6 and native Windows PowerShell 5.1.26100.9444. All
per-input counts, statuses, profiles and coverage agree between editions. All 376
original files retained their SHA-256 identities and modification timestamps.

names, paths and identity mapping remain local outside Git. This report uses S01–S15.

The historical route reproduces 14 `Completed`, one `CompletedWithCollectionGaps`,
zero scanner failures, 26 sequences, 45 BXI XML records, 384 evidence records and
189 references. Enabling the already implemented optional SUXI capability retains
those sequence/BXI/reference counts, inventories 11 v4 XML documents separately,
and increases evidence to 454. No production code was changed in this activity.

The source-data audit found two dangling historical fragment references in S10.
The known S03 delete link is structurally correct. The engine does not validate
these lifecycle links automatically. Two S11 cross-dossier targets physically
exist, but remain unsafe. There are no confirmed missing physical targets or
checksum mismatches among the collected v3 references.

Scanner completion is not identification success, regulatory validation or
migration readiness. No approved assessment configuration was supplied, so formal
T4 dossier identification was not executed on the local samples. T4 itself was
tested against its accepted engine/oracle suite.

### Five zero-BXI-XML inputs

S01/S12/S13 use unpadded `1`/`2` unit folders; S14/S15 use such folders below
a numeric wrapper, with three units in S15. All contain `submissionunit.xml`,
not v3 `index.xml` backbones. All 11 XML documents parse with recognized
`PORP_IN000001UV` / `urn:hl7-org:v3` structures. RepositoryDiscovery records
these as `SubmissionUnitFolder`, not exact v3 sequence folders. BXI intentionally
selects exact v3 folders; SUXI consumes the separate unit candidates.

Thus the old zero XML count was neither missing source XML nor failed v3
recognition: SUXI had not been enabled and its array was not counted. Six units
have recognized ICH/regional markers; five have `UnrecognizedProfileMarker` and
unrecognized coded fields. S14/S15 declare JP identifiers outside the current
bounded vocabulary. Four recognized EU units also retain
`ProfileSourceUnpublished`; this is not a regulatory endorsement of that profile.
All 11 retain `SchemaValidation=NotEvaluated` and
`ExternalReferenceNotResolved`. Their diagnostics count 63 document elements,
whose file targets/checksums are not part of the v3 reference result.

### XML and evidence consistency

The 45 BXI rows comprise 35 parsed physical XML documents and 10 missing EU
compatibility probes. Physical XML consists of 15 common backbones, five EU,
three US and 12 Other documents. Other documents include CA-folder regional
XML, SPL/STF/support XML and a wrapper-level activity XML; supported canonical
EU/US backbones are not mislabeled Other. All eight EU/US regional signatures
match physical path plus exact root/namespace evidence. No parsed US document
receives an EU envelope object or EU-specific field coverage.

The ten `MissingRegionalBackbone` observations do not become regulatory findings.
All XML/SUXI existence flags agree with physical checks; every input's physical
file count agrees with discovery. Same-named and numeric wrappers are preserved
in local source paths and do not erase the inspected dossier/unit relationships.
